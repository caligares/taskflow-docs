## Error response format

All errors follow this structure:

```json
{
  "error": "Not Found",
  "message": "No project found with project_id 'abc123'."
}
```

- `error` — a short, consistent error type (useful for programmatic handling)
- `message` — a plain-English explanation of what went wrong

---

## Status codes

### 400 Bad Request

The request body is missing a required field or contains an invalid value.

**Common causes and exact messages:**

| Mistake | Error message |
|---------|--------------|
| Missing `name` on `POST /projects` | `"The 'name' field is required and must be a non-empty string."` |
| Missing `title` on `POST /tasks` | `"The 'title' field is required and must be a non-empty string."` |
| Invalid `status` value | `"Invalid status 'Done'. Allowed values are: pending, in_progress, done."` |

<Note>
  Status values are **case-sensitive**. `"done"` works. `"Done"` and `"DONE"` return 400.
</Note>

<Note>
  Unknown fields (e.g. `"prioridade": "alta"`) are silently ignored — the API processes the valid fields and returns success.
</Note>

**Fix:** Check the request body against the [API Reference](/api-reference/overview). Ensure all required fields are present and values match the expected types.

---

### 401 Unauthorized

The `Authorization` header is missing or the API key is invalid.

**Example:**
```json
{
  "error": "Unauthorized",
  "message": "Missing or invalid API key. Provide a valid key in the Authorization header as: Bearer <api_key>"
}
```

**Fix:** Add the header `Authorization: Bearer tf-live-4a8f2c1e9b3d7e6a` to your request. Make sure there are no extra spaces and the `Bearer ` prefix is included. See [Authentication](/authentication) for details.

---

### 404 Not Found

The resource referenced in the URL or request body does not exist.

**Example — project not found:**
```json
{
  "error": "Not Found",
  "message": "No project found with project_id 'abc123'."
}
```

**Example — task not found:**
```json
{
  "error": "Not Found",
  "message": "No task found with task_id 'abc123'."
}
```

**Common causes:**
- Using a `project_id` or `task_id` that was never created
- A typo in the ID
- Attempting to update or delete a task that was already deleted

**Fix:** Verify the ID you are using. Retrieve IDs from the response of `POST /projects` or `POST /tasks`.

## Handling errors in code

<CodeGroup>

```python Python
import requests

response = requests.post(
    "https://test-writechoice.onrender.com/tasks",
    headers={"Authorization": "Bearer tf-live-4a8f2c1e9b3d7e6a"},
    json={"project_id": "invalid-id", "title": "My task"}
)

if response.status_code == 404:
    error = response.json()
    print(f"Not found: {error['message']}")
elif response.status_code == 400:
    error = response.json()
    print(f"Bad request: {error['message']}")
elif response.ok:
    task = response.json()
    print(f"Created task: {task['task_id']}")
```

```js JavaScript
const response = await fetch("https://test-writechoice.onrender.com/tasks", {
  method: "POST",
  headers: {
    "Authorization": "Bearer tf-live-4a8f2c1e9b3d7e6a",
    "Content-Type": "application/json"
  },
  body: JSON.stringify({ project_id: "invalid-id", title: "My task" })
});

const data = await response.json();

if (!response.ok) {
  console.error(`${response.status} ${data.error}: ${data.message}`);
} else {
  console.log("Created task:", data.task_id);
}
```

</CodeGroup>

## Quick reference

| Code | Error | Likely cause |
|------|-------|--------------|
| `400` | Bad Request | Missing or invalid field in request body |
| `401` | Unauthorized | Missing or invalid API key |
| `404` | Not Found | Referenced project or task does not exist |
